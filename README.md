# ExamNotes AI

ExamNotes AI is a full-stack AI study assistant that turns a topic into structured, exam-focused study material. Users can choose their class or level, exam type, revision mode, diagrams, and charts, then generate notes with Gemini and export the result as a printable PDF.

## GitHub Introduction

> I built ExamNotes AI as a production-style AI study workflow rather than a one-off chatbot. A user signs in with Google, enters a topic and exam context, and receives structured notes generated by Gemini. The application supports short revision mode, important-topic prioritisation, Mermaid diagrams, Recharts-compatible data, exam questions, note history, PDF export, and a credit-based usage model. I implemented the React frontend, Express API, MongoDB persistence, JWT cookie authentication, Stripe checkout and webhook handling, and deployed the application on Render. The project demonstrates how I handled structured AI output, authenticated user data, asynchronous generation, failure states, and a complete user flow from generation to payment and download.

## Why This Project

Most AI note generators return an unstructured block of text. ExamNotes AI uses a strict response contract so the frontend can render notes as separate sections:

- Topic importance and prioritised sub-topics
- Detailed notes or concise last-minute revision points
- Short and long exam questions
- Optional Mermaid flow diagrams
- Optional chart data for visual summaries
- Printable PDF output

Each generated note costs 10 credits. New users receive 50 credits, and additional credit packs can be purchased through Stripe Checkout.

## Features

- Google authentication with protected application routes
- AI-generated, exam-oriented notes using Gemini
- Class or level and exam-type context in each generation request
- Detailed mode and short revision mode
- Optional Mermaid diagrams and chart data
- Notes saved to MongoDB and available in user history

- Credit balance tracking and validation before AI generation
- Stripe Checkout credit packs with webhook-based credit updates
- Responsive React interface with Motion animations
- Separate frontend and backend services suitable for Render deployment

## Application Flow

1. The user signs in with Google.
2. The backend creates or finds the user and sets an HTTP-only JWT cookie.
3. The user submits a topic, level, exam type, and output preferences.
4. The backend checks the user's credit balance and builds a constrained prompt.
5. Gemini returns JSON matching the application's note schema.
6. The backend stores the generated note in MongoDB and deducts 10 credits.
7. The frontend renders the result and can request a PDF export.
8. Users can revisit saved notes from their history or buy more credits through Stripe.

## API Surface

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `POST` | `/api/auth/google` | Create or sign in a Google-authenticated user |
| `GET` | `/api/auth/logout` | Clear the authentication cookie |
| `GET` | `/api/user/currentuser` | Return the authenticated user |
| `POST` | `/api/notes/generate-notes` | Generate and save AI notes |
| `GET` | `/api/notes/getnotes` | List the authenticated user's notes |
| `GET` | `/api/notes/:id` | Load one note owned by the authenticated user |
| `POST` | `/api/pdf/generate-pdf` | Generate a PDF from note content |
| `POST` | `/api/credit/order` | Create a Stripe Checkout session |
| `POST` | `/api/credits/webhook` | Add credits after a verified Stripe payment |

## Environment Variables

Create a `.env` file in `backend/`:

```env
PORT=5000
MONGODB_URL=your_mongodb_connection_string
JWT_SECRET=your_jwt_secret
GEMINI_API_KEY=your_gemini_api_key
STRIPE_SECRET_KEY=your_stripe_secret_key
STRIPE_WEBHOOK_SECRET=your_stripe_webhook_secret
CLIENT_URL=your_frontend_url
```

Create a `.env` file in `frontend/`:

```env
VITE_FIREBASE_APIKEY=your_firebase_api_key
```

Configure the Firebase project for Google sign-in and configure the Stripe webhook endpoint as `/api/credits/webhook`. Never commit secret keys to GitHub.

## Deployment

The application is deployed as separate frontend and backend services on Render.

Recommended Render configuration:

- **Backend:** deploy `backend/` as a Node web service, use `npm install` as the build command, and use `node index.js` as the start command.
- **Frontend:** deploy `frontend/` as a static site with `npm install && npm run build` and publish the `dist` directory.
- Add the backend environment variables to the backend service and the Firebase variable to the frontend service.
- Set the frontend API base URL to the deployed backend URL and set `CLIENT_URL` to the deployed frontend URL.
- Register the deployed backend webhook URL with Stripe.

## Engineering Highlights

### Structured AI output

The prompt builder asks Gemini for strict JSON with a known schema. This lets the frontend render different content types predictably instead of parsing free-form prose.

### Authenticated ownership

Protected routes receive the user identity from a JWT cookie. Note queries include both the note ID and the authenticated user ID, preventing one user from loading another user's saved note through the API.

### Payment-driven credits

Credit packs are mapped to fixed server-side values. Stripe metadata carries the user ID and credit amount, and the webhook updates the user's balance only after Stripe verifies the event signature.

### Failure-aware generation

The API validates the topic and available credits before calling Gemini. The frontend exposes loading progress, generation errors, and the remaining credit balance after a successful request.
